# 담당 4 번식 충돌 처리와 잡초 생성 구현 보고서

담당 4는 자동 생성 후보 선택, 현재 빈 칸 기준 번식 배치, 잡초 후보 생성과 수확 이벤트 전달을 구현했다. PR [#13](https://github.com/lyemee/DesignPattern26-2/pull/13)과 [#17](https://github.com/lyemee/DesignPattern26-2/pull/17)이 main에 반영됐으며, PR [#20](https://github.com/lyemee/DesignPattern26-2/pull/20)의 실제 State·Lifecycle과 연결한 통합 테스트까지 완료했다. 기능 검증 기준 main은 `59e01d5`이다.

## 구현 범위와 다른 담당자의 책임

| 범위 | 담당 4의 구현 |
| --- | --- |
| 자동 생성 후보 선택 | `CandidateSelectionPolicy<T>`와 `UniformSelectionPolicy<T>`, 선택 계약 단위 테스트 |
| 현재 점유 상태 조회 | `CellReport.currentCell()`과 Resident의 현재 생존 여부 보고 연결 |
| 번식 배치 | `GenerationManager`에서 현재 빈 칸 스냅샷, 꽃 번식 요청·일반 탄생 후보 수집, 좌표별 균등 선택과 배치 |
| 잡초 생성 | 현재 빈 칸의 위치 추첨, 잡초 후보 하나 추가, 다른 후보와 균등 경쟁 |
| 화면 tick 연결 | `Universe`에서 매 세대 잡초 요청, `GameSession`에서 확장 모드에만 적용 |
| 수확 전달 | 같은 `collect()`에서 수확 이벤트를 모아 `GenerationResult.harvested()`로 반환 |
| 통합 | 기존 수확 집계·Undo를 보존하고 일반 세대와 잡초 요청 세대를 공통 경로에서 처리 |

구체 식물·번식 좌표 알고리즘과 `WeedFactory`는 #3의 구현을 재사용했다. 성장 State·생존·시듦·회복·규칙 탄생·꽃 소멸은 #20의 구현이며, 수확 카운터·보드 스냅샷·Undo의 기본 구현은 #16의 기능을 재사용했다. 담당 4는 이 기능들을 세대 처리에 연결하고 통합 계약을 검증했다.

## 확정한 게임 규칙

- 번식 대상은 현재 죽어 있는 보드 안의 칸이다. 현재 점유된 칸은 이번 계산에서 죽더라도 제외한다.
- 사용자 클릭은 추첨 후보에 넣지 않는다. 클릭과 세대 처리는 GameSession의 동기화 범위로 분리되며, 직접 심어 현재 점유된 칸은 자동 생성이 덮어쓰지 않는다.
- 꽃은 현재 꽃 단계이고 Life 생존 조건을 충족하며 주변 잡초에 막히지 않을 때만 번식·소멸한다. 생존 실패 시 번식 없이 사망하고, 잡초에 막힌 생존 꽃은 꽃 단계를 유지한다. 이 규칙은 최종적으로 #20의 구현에 맞춰 확정했다.
- 일반 탄생·꽃 번식·잡초 후보는 출처나 종류에 우선순위를 두지 않고 같은 좌표의 후보 목록에서 경쟁한다.
- 확장 모드는 자동 실행·수동 진행 모두 매 세대 잡초 후보 하나를 요청한다. 빈 칸이 없거나 경쟁에서 지면 실제 잡초는 생성되지 않을 수 있다. 일반 모드는 잡초 요청을 무시한다.

## 세대 처리 흐름

1. `figureNextState()`에서 모든 셀이 현재 상태를 읽고 다음 상태와 번식·수확 신호를 계산한다.
2. `collect()`에서 현재 점유 여부, 일반 탄생 후보, 꽃 번식 요청, 수확 이벤트를 함께 수집한다. 모든 꽃은 같은 `SeedField` 스냅샷을 조회한다. 잡초 요청이 있으면 현재 빈 칸 한 곳을 추첨해 후보를 추가한다.
3. 좌표별 후보 하나를 균등 선택한다. 일반 탄생이 선택되면 기존 계산 결과를 보존하고, 꽃·잡초가 선택되면 `board.apply()`와 `sow()`로 다음 상태에 기록한다.
4. `transition()`으로 다음 상태를 한 번에 반영한다. 수확 목록은 `GenerationResult`로 반환하고 GameSession이 집계와 Undo 이력 저장을 수행한다.

셀은 좌표를 저장하지 않는다. Neighborhood가 순회하며 좌표를 전달하고, 매니저가 꽃의 `seedTargets(position, field, random)`에 원점과 조회 인터페이스를 제공한다. 빈 칸 판단과 발생 신호 생성은 서로 다른 책임이며, 매니저가 꽃의 생존 조건을 다시 판정하지 않는다.

## 적용한 설계와 선택 이유

### Strategy

선택 알고리즘을 세대 처리에서 분리하고 독립적으로 검증하기 위해 Strategy를 적용했다. 정책은 Plant·Resident에 의존하지 않는 제네릭 인터페이스이고, 매니저는 좌표별 후보 경쟁과 잡초 위치 추첨에 같은 균등 정책을 재사용한다.

각 목록 항목은 같은 선택 확률을 갖는다. `[A1, A2, B1]`이면 각 항목은 1/3이고 종류 A의 합계 확률은 2/3이다. 선택 정책과 매니저는 전달받은 후보를 종류별로 합치거나 중복 제거하지 않는다. 정책은 선택된 원본 객체를 반환하며 목록과 후보를 변경하지 않는다.

향후 정책 교체가 가능한 것은 부가적인 확장 가능성이다. 현재 요구사항에 없는 우선순위·가중치 정책, 정책 선택 enum, Factory·Registry는 추가하지 않았다.

### 책임 분리와 조회 인터페이스

Resident는 현재 생존 여부와 계산 결과라는 사실만 보고한다. 매니저는 번식 대상 판단·후보 수집·선택·배치를 담당한다. `SeedField`는 현재 빈 칸 여부와 보드 크기만 제공하므로 꽃은 보드 내부 구조나 배치 API에 의존하지 않는다.

기존 `CellAction`을 통한 `apply()`·`sow()` 경로와 #16의 스냅샷·Undo 경로를 재사용했다. Command·Memento 구조 자체를 담당 4가 새로 도입한 것으로 설명하지 않는다.

### 지연 초기화

잡초 추첨에만 필요한 빈 칸 `Point` 목록은 처음 요청될 때 생성하고 같은 세대에서 재사용한다. collect 순서는 정수 좌표로 기록해 기존 중첩 보드 순회와 같은 난수 인덱스의 선택 결과를 유지한다. 스냅샷은 세대마다 새로 생성하므로 이전 세대의 캐시가 다음 세대에 섞이지 않는다.

이는 Lazy Initialization이며 GoF 패턴은 아니다. 잡초를 요청하지 않는 경로의 불필요한 Point 할당을 줄이는 변경이다. 확장 모드는 매 세대 목록을 사용하며 실행 시간 개선 수치를 측정하지는 않았다. 목록을 만들기 위한 추가 보드 collect는 없다.

## 계약과 고려한 대안

- 정책은 null 목록·Random·후보 항목을 난수 소비 전에 거부한다. 빈 목록은 빈 결과, 단일 후보는 해당 객체를 난수 호출 없이 반환한다. 둘 이상이면 `nextInt(후보 수)`를 정확히 한 번 호출한다.
- Random은 외부에서 전달받는다. 세대 처리 내부의 별도 Random 생성이나 seed 재설정 없이 기존 공유 구조를 유지했다.
- 수확 이벤트는 보고 순서·원본 Plant 참조·반복 항목을 유지하고 `List.copyOf()`로 반환한다. transition의 신호 초기화와 다음 세대 처리로 이전 결과가 변경되지 않는다.
- 꽃마다 즉시 배치하면 순회 순서에 따라 선점하므로, 후보 수집을 끝낸 뒤 선택·배치한다.
- 다음 세대의 빈 칸을 다시 구하는 방식은 확정된 현재 빈 칸 규칙과 맞지 않아 사용하지 않는다. `hasSurvivingPlant`는 기존 보고 계약에 남아 있지만 매니저의 번식 대상 판단에는 쓰지 않는다.
- 반영 후 잡초를 별도 생성하면 다른 자동 생성과 경쟁하지 않으므로, 반영 전 후보 목록에 합친다.
- 사용되지 않는 단일 인자 `seedTargets(Point)`는 제거하고 3인자 계약으로 통일했다.

## 검증 결과

`mvn -B -ntp compile test`에서 전체 **149개 테스트가 통과**했다. 실패·오류·건너뜀은 모두 0개다. 이 수치는 팀 전체 테스트 수이며, 담당 4가 작성한 테스트 수를 의미하지 않는다.

담당 4의 테스트는 선택 계약, 현재 점유·경계 보호, 반복 후보 유지, 후보별 선택 가능성, 난수 호출 횟수와 seed 재현성, 세대별 스냅샷·캐시 격리, 수확 이벤트 전달과 Undo를 검증한다. 불안정한 대량 추첨 비율 테스트는 사용하지 않았다.

`GenerationLifecycleIntegrationTest`는 실제 State·Lifecycle로 다음 다섯 경로를 검증한다.

1. 보드 초기화 없이 잡초 8세대를 연속 진행하고 전체 Undo로 복원
2. 생존 조건을 못 채운 성숙 꽃이 좌표 요청 없이 사망
3. 잡초에 막힌 생존 꽃이 꽃 단계를 유지하고 번식하지 않음
4. 생존한 성숙 꽃이 현재 빈 칸에 씨를 뿌리고 소멸
5. 실제 수확과 잡초 생성이 함께 일어난 tick을 Undo해 열매 단계·수확량·잡초 위치 복원

GUI에서는 테스트 창 실행, 일반 셀 클릭과 Undo 복원을 확인했다. 메뉴를 통한 자동·수동 진행, 모드 전환과 잡초 화면 확인은 사용자 담당으로 남겼으며 완료로 집계하지 않았다. 같은 게임 처리 경로의 기능 검증은 위 자동화 테스트 결과를 따른다.
